1. 什么是 Git？
Git 是一个分布式版本控制系统（Version Control System）。
简单理解：
> Git 就像代码的“时光机”，能够记录每一次修改，并且随时回到之前的版本。
例如：
你今天写了一个聊天机器人：
print("Hello")
明天改成：
print("Hello AI")
后天又改坏了。
有了 Git：
git log
查看历史版本。
git checkout 版本号
回到以前的代码。
---
Git 的作用
记录代码历史
回退代码版本
多人协作开发
防止代码丢失

为什么要环境隔离？
环境隔离可以避免不同项目之间的依赖冲突，使项目运行更加稳定，并提高可维护性和可复现性。
pip freeze 作用？
pip freeze 用于查看当前环境中的所有依赖及版本信息，常用于生成 requirements.txt 文件。
如何复现别人项目？
1. 下载项目代码；
2. 创建并激活对应的虚拟环境；
3. 根据 requirements.txt 安装依赖；
4. 按照 README.md 的说明运行项目；
5. 成功运行后即完成项目复现。
---
结合你之前做过的 LeRobot 复现、DeepSeek API 调用、本地模型部署，其实你已经在实践“项目复现”了。只是以前是在跟着教程操作，现在开始要理解背后的工程化思想：环境隔离 → 依赖管理 → 项目复现 → 版本控制（Git）。这四个概念是 Day 6 最核心的内容。



使用 Anaconda 创建独立虚拟环境的主要目的是？
A.提高计算机性能
B.隔离不同项目的 Python 环境和包依赖
C.加速模型训练
D.优化数据存储
1. Anaconda 虚拟环境目的：B
虚拟环境的作用是隔离项目。
比如：
项目A 需要 Python3.10 + requests 项目B 需要 Python3.8 + 旧版本 numpy
如果混在一起，依赖可能冲突。Anaconda 虚拟环境可以让每个项目有自己的 Python 和包。
所以选 B。

关于 Anaconda 虚拟环境与 Docker 容器，以下描述正确的是？
A.Anaconda 虚拟环境用于隔离 Python 运行环境，Docker 容器用于隔离操作系统环境
B.Anaconda 虚拟环境只能管理 Python 包，Docker 容器只能管理系统级软件
C.Anaconda 虚拟环境无法在不同操作系统间迁移，Docker 容器也不能
D.Anaconda 虚拟环境与 Docker 容器的创建和管理命令完全相同
2. Anaconda 与 Docker：A
Anaconda 主要隔离：
Python版本 Python依赖包
Docker 隔离得更完整，包括：
操作系统环境 系统依赖 Python环境 项目代码 运行命令
所以：
conda 是 Python 层面的隔离 Docker 是系统运行环境层面的隔离
选 A。

Anaconda 创建虚拟环境时，默认使用的 Python 版本是？
A.Python3.6
B.Python3.7
C.Python3.8
D.与系统默认 Python 版本一致
3. Anaconda 创建虚拟环境默认 Python 版本：D
如果你创建环境时没有指定版本，比如：
conda create -n test
它通常会跟随当前配置或默认 Python 版本。
如果你想明确版本，要写：
conda create -n ai python=3.10
所以这题选 D：与系统默认 Python 版本一致。
比赛里先按题库答案记 D。

使用 conda env export 命令将 Anaconda 虚拟环境配置导出为 YAML 文件后，在不同操作系统之间迁移虚拟环境无需重新安装任何依赖包。
对 / 错
4. conda env export 后跨系统无需重装依赖：错
conda env export 可以导出环境配置，比如：
conda env export > environment.yml
别人可以用它重建环境：
conda env create -f environment.yml
但不是“无需重新安装依赖包”。到了另一台电脑，还是要根据配置重新下载和安装依赖。
而且 Windows、Linux、macOS 之间有些包还不完全一样。
所以是 错。

仅复制 Anaconda 虚拟环境文件夹，就能保证在其他机器上正常使用该虚拟环境。
对 / 错
5. 仅复制虚拟环境文件夹就能迁移：错
不能简单把整个环境文件夹复制到另一台电脑就保证能跑。
原因是环境里可能包含：
绝对路径 系统相关文件 平台相关依赖 本机配置
更推荐：
pip freeze > requirements.txt
或者：
conda env export > environment.yml
所以是 错。

使用 Python 的 Pandas 库的 read_csv() 函数读取 CSV 格式数据集时，会自动处理数据中的缺失值。
对 / 错
19. read_csv() 会自动处理缺失值：错
read_csv() 的作用是读取 CSV 文件。
它会把一些空值识别成缺失值，比如 NaN，但不会自动帮你完成真正的数据清洗。
你还需要自己处理，比如：
df.dropna() # 删除缺失值 df.fillna(0) # 用0填充缺失值
所以“自动处理缺失值”是 错。

Day6 的核心是：
让你的项目在自己电脑能跑，也能上传 GitHub，别人下载后也知道怎么安装依赖、怎么运行。
所以今天重点是：
Git：保存代码版本 conda：管理 Python 环境 requirements.txt：记录项目依赖 README：说明项目怎么用 Docker：更完整地封装运行环境
Day6 实操重点
你今天项目要完成这三个文件/状态：
1. Git仓库 2. requirements.txt 3. README.md
常用命令：
git status git add . git commit -m "day6" git push
生成依赖文件：
pip freeze > requirements.txt
README 可以写这些内容：
项目名称 项目介绍 环境要求 安装依赖 运行方式 功能说明
别人看到你的 GitHub 项目，应该能知道：
这个项目是干什么的 需要安装什么 怎么运行 怎么退出
