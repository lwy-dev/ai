一、什么是“大模型”（LLM）
“大模型”本质上：
是一个“看过海量数据”的超级文字大脑。
比如：
看过大量网页
看过代码
看过书
看过论文
看过聊天记录
看过各种问答
最后它学会了：
人类怎么说话
怎么写代码
怎么回答问题
怎么推理
怎么总结
你可以把它理解成：
像一个：
超级学霸
超级搜索记忆库
超级语言推理器
但它：
❌ 不是“真正理解世界”
而是：
✅ 非常会“预测下一句话”
举个例子
你输入：
“今天天气很好，我想去……”
普通程序：
不知道后面是什么
大模型：
会预测：
散步
公园
旅游
打篮球
因为它见过无数类似句子。
为什么叫“大”模型？
因为它参数很多。
参数你可以理解成：
大脑里的“神经连接数量”
比如：
小模型：几百万参数
中模型：几亿参数
大模型：几百亿参数
参数越多：
通常：
理解越强
推理越强
代码越强
对话越自然
现在常见的大模型
比如：
OpenAI 的 GPT
Google 的 Gemini
Anthropic 的 Claude
DeepSeek 的 DeepSeek
它们本质上：
都是“大脑”。
二、什么是 Prompt（提示词）
Prompt：
其实就是：
你给 AI 的“指令”。
比如：
你输入：
“帮我写一篇演讲稿”
这句话：
就是 Prompt。
Prompt 为什么重要？
因为：
AI 很聪明，
但：
你说得越清楚， 它越知道你想干什么。
举例
普通 Prompt
帮我写代码
AI：
不知道你要什么。
好 Prompt
用 Python 写一个机械臂控制程序
要支持摄像头识别
使用 OpenCV
输出串口控制指令
这时候：
AI 输出会好很多。
Prompt 工程是什么？
就是：
“如何更专业地和 AI 沟通”
包括：
怎么提问
怎么给规则
怎么给上下文
怎么限制输出格式
你现在其实已经在做 Prompt 了
比如你会说：
“详细一点”
“通俗易懂”
“一步一步教我”
“给我完整代码”
这些都属于：
Prompt 技巧。

API 非常重要。
一句话：
API = 别人的功能接口
你可以理解成：
“遥控器”
你不用知道电视内部怎么工作，
你只要：
按按钮。
AI API 是什么？
比如：
你自己的程序：
想调用 GPT。

你不可能自己训练 GPT。
于是：
给你一个接口。
你程序里：
发一句话：
你好

你好！有什么可以帮你？
这就是：
程序调用 AI。
API 的本质
你可以理解成：
现实世界            编程世界

四、什么是 RAG
RAG 是很多人最容易懵的。
其实它非常简单。
RAG 全称：
Retrieval-Augmented Generation
中文：
检索增强生成
听起来很吓人。
但本质：
就一句话：
“先查资料，再让 AI 回答”
为什么需要 RAG？
因为：
大模型：
❌ 不是实时知道所有东西
比如：
你公司内部文档， 比赛规则， PDF， 你的数据集，
模型训练时没见过。
怎么办？
RAG 工作流程
第一步
先：
“搜索相关资料”
比如：
PDF
本地文档
数据库
网页
第二步
把找到的内容：
塞给 AI。
第三步
AI 再回答。
举个真实例子
比如：
你问：
“比赛规则里机器人最大尺寸是多少？”
普通 AI：
可能不知道。
但 RAG 会：
先搜索 PDF
找到： “机器人尺寸不得超过……”
再回答你
所以：
RAG = AI + 搜索系统
现在很多 AI 产品都在用 RAG
比如：
AI 客服
AI 法律助手
AI 医疗问答
企业知识库
PDF 问答

什么是分支（Branch）？
分支可以理解成：
> 一条独立的开发线路。
例如：
main
 │
 ├── 功能A开发
 │
 └── 功能B开发
每个人都可以在自己的分支上修改代码。
不会影响主分支。
---
为什么需要分支？
假设你有一个聊天机器人项目：
chatbot.py
现在想增加：
语音功能
但还没写完。
如果直接改：
main
可能把项目搞坏。
所以创建一个新分支：
voice-feature
在里面开发。
开发完成后再合并。
---
Git常见分支
现代项目一般这样：
main
主分支。
稳定版本。
---
dev
开发分支。
---
feature/login
登录功能开发。
---
feature/chatbot
聊天机器人开发。
---

普通大模型：
你问它，它直接根据自己脑子里的知识回答。
RAG：
先去资料库里查相关内容，再把查到的内容交给大模型，让它结合资料回答。
所以核心流程是：
用户问题 -> 检索相关资料 -> 把资料和问题交给大模型 -> 生成答案
因此选 B。

19. 判断：调整 Prompt 无法提升推理能力。错
这句话是错的。

比如：

和：

第二种通常回答更清楚、更稳定。

判断：在使用 RAG（检索增强生成）技术时，不需要对文档数据进行向量化处理。
对 / 错
20. 判断：RAG 不需要对文档向量化。错
RAG 通常需要把文档转成向量。
为什么？
因为计算机不懂文字的“意思”，但可以比较向量距离。向量越接近，说明语义越相似。
例如用户问：
如何创建conda虚拟环境？
系统可能检索到：
conda create -n ai python=3.10
这就是通过语义相似度找到相关内容。
所以 RAG 通常需要：
文档 -> 向量 -> 向量数据库 -> 检索
这题说“不需要向量化”，所以是错的。
