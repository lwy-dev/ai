1. API 是什么？
API 本质：
“程序和程序之间交流的方法”
---
举例（最容易懂）
你去奶茶店：
你：
“一杯珍珠奶茶”
店员：
“好的”
然后厨房开始做。
这里：
店员
就是 API
---
为什么？
因为：
你不能直接进厨房
你必须通过：
一个“接口”
来交流。
---
AI里的 API
你的程序：
“DeepSeek，请回答问题”
DeepSeek：
“好的，这是答案”
中间这套通信规则：
就叫 API
---
你现在写的：
requests.post()
本质：
就是在调用 API
---
你现在可以这样记：
API =
“程序之间的电话”
---

你可以把它们理解成：
requests
是：
“打电话的工具”
GET请求
是：
“去拿东西”
POST请求
是：
“提交东西”
---
我用现实例子给你讲（最容易懂）
假设：
你在点外卖。
---
GET 请求是什么？
你打开外卖软件：
“我要看看附近有什么店”
这时候：
你只是：
获取信息
没有提交数据。
所以：
GET = 获取数据
---
对应代码
import requests
res = requests.get("https://httpbin.org/get")
print(res.text)
意思：
Python去访问这个网址
然后把内容拿回来
---
GET 请求常见场景
场景	是否GET
看网页	✅
搜索新闻	✅
获取天气	✅
获取AI模型列表	✅
因为：
只是“拿数据”
---
POST 请求是什么？
现在：
你开始下单。
你输入：
奶茶
少糖
加冰
然后：
点击：
提交订单
这时候：
你是在：
向服务器提交数据
所以：
POST = 提交数据
---
AI为什么必须用POST？
因为：
你要提交：
你的问题
聊天记录
模型参数
身份设定
例如：
“请帮我写代码”
这属于：
提交内容
所以：
AI接口基本都用 POST。
---
POST代码长这样
import requests
data = {
    "message": "你好"
}
res = requests.post(
    "网址",
    json=data
)
print(res.text)
---
requests 是什么？
requests 是 Python 的一个库。
作用：
让Python拥有联网能力
---
没有requests
Python：
不会联网
不会发请求
---
有requests
Python就能：
访问网页
调用AI
登录网站
下载数据
上传内容
---
你可以这样理解
requests 就像：
快递员
---
GET
像：
“帮我去拿快递”
---
POST
像：
“帮我把东西寄出去”
---
最核心区别（你必须记住）
GET         	POST
获取数据	    提交数据
看东西	        发东西
参数通常在网址	数据通常在请求体
一般用于查询	一般用于AI/登录/上传

A.卷积层
B.循环层

1. Transformer 的核心组件：C.注意力机制
Transformer 是现在大语言模型的核心架构之一。它最重要的机制叫 Attention 注意力机制。
通俗理解：
一句话里不是每个词都同样重要，注意力机制会帮模型判断“现在应该重点看哪些词”。
比如：
小明把书给了小红，因为她明天要考试。
模型要理解“她”指谁，就需要关注前面的“小红”。
所以选 C。

判断题：在使用 LangChain 优化与 DeepSeek 的交互时，load_memory 函数可以直接加载外部知识库，增强模型回答的专业性。
对 / 错
16. load_memory 直接加载外部知识库：错
这题容易误解。
Memory 通常是“对话记忆”，比如保存你前面说过什么。
外部知识库一般不是靠 load_memory 直接加载，而是用 RAG：
文档 -> 切分 -> 向量化 -> 向量数据库 -> 检索 -> 给大模型
所以这句话是 错。

判断题：通过调整 Prompt 的结构和内容，无法提升 DeepSeek 大模型的推理能力。
对 / 错
17. 调整 Prompt 无法提升推理能力：错
这句话也是错的。
Prompt 写得好，模型回答质量会明显变化。
差的 Prompt：
写代码。
好的 Prompt：
请用 Python requests 调用 DeepSeek API，实现用户输入问题后打印 AI 回复。要求代码适合初学者，并解释每一步。
第二种更明确，AI 更容易给出可用结果。
所以是 错。

A.加载环境变量：比如 API Key B.初始化客户端：告诉程序要调用 DeepSeek C.设置页面配置：如果用 Streamlit，需要设置标题等 D.初始化会话状态：保存聊天记录
所以选 ABCD。
对应代码大概是这种思路：
messages = [ {"role": "system", "content": "你是一个有帮助的AI助手"} ]
这个 messages 就是后面多轮对话的基础。

项目题：DeepSeek 聊天助手的对话流程包括哪些？
A.用户输入问题
B.将用户消息添加到历史记录
C.调用 DeepSeek API 获取响应
D.将 AI 响应添加到历史记录
20. 对话流程：ABCD
一个多轮聊天程序的基本流程是：
1. 用户输入问题 2. 把用户问题加入历史记录 3. 调用 DeepSeek API 4. 把 AI 回复也加入历史记录 5. 打印 AI 回复 6. 等用户继续输入
所以 A、B、C、D 全部正确。
你今天写代码时，核心就是维护这个列表：
messages = [ {"role": "system", "content": "你是一个有帮助的AI助手"} ] while True:
user_input = input("你：")
messages.append({"role": "user", "content": user_input}) # 调用 		DeepSeek API，拿到 ai_response
messages.append({"role": "assistant", "content": ai_response}) 		print("AI：", ai_response)
这就是“多轮提问”的关键。


Day2 最重要的知识串起来
今天你要理解的是：
requests：Python 里发网络请求的库
POST请求：把数据提交给服务器
JSON：接口之间传数据的常见格式
API：别人开放给你调用的功能入口
DeepSeek API：你把问题发过去，它返回 AI 答案
messages：保存多轮对话历史
LangChain：以后帮你更方便地组织 Prompt、模型、记忆、工具和知识库 Transformer：大模型底层的重要架构
